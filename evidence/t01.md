# T-01 记忆字符上限与超限响应

## 验收结论

`MemoryStore` 默认对 `MEMORY.md` 使用 2,200 字符、对 `USER.md` 使用 1,375 字符；配置加载路径允许用户配置覆盖。写入先验证最终内容长度，失败时不提交、不截断原文件。超限错误现在返回“当前还可用多少字符”，符合 PRD §7.2。

## 实现

- `tools/memory_tool_store.py::_over_limit` 用当前条目长度计算剩余可用字符数，而不是报告超限差值。
- `MemoryStore.add` 的单条超限错误同样返回当前剩余可用字符数，保留原有批量整理指引。

## 验证

- 手动自检命令：`.venv\Scripts\python.exe -c "from tools.memory_tool_store import MemoryStore; import tempfile; from pathlib import Path; import tools.memory_tool as m; d=Path(tempfile.mkdtemp()); m.get_memory_dir=lambda:d; s=MemoryStore(memory_char_limit=10,user_char_limit=5); s.load_from_disk(); s.add('memory','123456789'); r=s.add('memory','x'); print(r['success'], r['error']); print((d/'MEMORY.md').read_text())"`
- 结果：超限结果为 `False`；消息给出 `1 chars remain available`；文件仍为 `123456789`，未截断。
- 已执行的仓库测试命令 `bash scripts/run_tests.sh tests/tools/test_memory_tool.py tests/agent/test_system_prompt.py` 在当前 Windows PowerShell 执行器下失败：`scripts/run_tests.sh: line 1: syntax error: bad substitution`，且脚本尝试加载不存在的 `D:/VSCodeProjects/hermes-agent/_activation.sh`。
- `.venv\Scripts\python.exe` 为 Python 3.14.2，但没有 `pytest`（`ModuleNotFoundError: No module named 'pytest'`）。因此行为自检通过；pytest 回归尚未验证。需在配置好的 POSIX shell / Hermes 测试环境提供 pytest 后运行 `scripts/run_tests.sh tests/tools/test_memory_tool.py`。
