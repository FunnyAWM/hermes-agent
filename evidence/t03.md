# T-03 / T-18 系统提示词顺序与根约定

状态：T-03 已完成（2026-11-03）；T-18 补根约定后于 2026-11-06 复验。

## 结论

拼装顺序为 **ROOT → SOUL → AGENTS → MEMORY → USER → NOTES INDEX → skills 索引 → 插件段 → profile → 时间 → 环境**。

- ROOT 是 `agent/system_prompt.py::MEMORY_ROOT_PROMPT`，stable 层第一段，先于 SOUL 与内置身份。
  七条约定：分层、按需读取、改前先读、`notes/docs/` 只读、保真、工具边界与 `SOUL.md`、
  自然回复。
- SOUL → AGENTS → MEMORY 连续，skills 索引不再位于 volatile 首位（T-03）。
- MEMORY / USER / NOTES 三段连续，中间不插入其它段。

## 边界

- 抓取脚本用 `sp._skills_prompt` 桩替代真实技能索引，只验证位置，不验证索引内容。
- ROOT 文本改动会使提示词前缀缓存失效；改动须随会话边界生效，不在会话中途重建。

## 2026-11-06 退出码复验

统一入口要求每条判据都有可判定的退出码，因此本轮补跑：

```bash
PYTHONUTF8=1 .venv/Scripts/python.exe scripts/capture_prompt_order.py   # exit 0
PYTHONUTF8=1 .venv/Scripts/python.exe scripts/verify_pc_memory_notes.py # exit 0
PYTHONUTF8=1 .venv/Scripts/python.exe scripts/verify_version_anchor.py --commit v0.22.5-fork.1  # exit 0
```

- 三条均 `RESULT: …` 后以 0 退出；`capture_prompt_order.py` 的临时目录改为
  `ignore_cleanup_errors=True`：脚本会 `chdir` 进临时 project 目录读 `AGENTS.md`，
  Windows 下目录被自身占用时清理会抛 `PermissionError`，判定结果不受影响，
  清理失败不应污染退出码。
- 不加 `PYTHONUTF8=1` 时，提示词正文里的中文与 emoji 会在 GBK 控制台触发
  `UnicodeEncodeError`；这是输出通道问题，不是拼装顺序问题（记录以免误判为回归）。
