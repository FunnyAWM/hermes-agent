# T-04 notes 分片与清单注入

状态:**已完成**(2026-11-03 收口)。实现、测试、PRD §7.1/§7.4 契约核对均齐。

## 实现

- `hermes_notes/store.py` + `hermes_notes/__init__.py`:固定 7 类英文目录/中文显示名单点映射
  (`work 工作 / study 学习 / life 生活 / health 健康 / finance 财务 / people 人际 / other 其他`,
  与 PRD §7.1 枚举表逐行一致)、严格写入类别校验、单层 topic 路径校验(拒 `..`、子路径、空)、
  递归扫描 Markdown front matter(`name`/`description`/`updated`)、未知目录读取时归 `other`。
- 清单最多 64 条,按 `updated` 倒序截断;**被截断的条数在清单尾部明示**
  (`(-N older notes beyond this index's 64-entry cap; …)`,PRD §7.4「不静默丢弃」),
  `NotesStore.omitted_count()` 供程序化读取。摘要压到 40 字符(单条约 100 tokens 的预算)。
  只渲染 `显示名/名称 — 摘要`,正文永不进提示词。
- `agent/system_prompt.py::_memory_parts` 在 USER 块后追加 `NOTES INDEX`,实际顺序
  SOUL → AGENTS → MEMORY → USER → NOTES INDEX → skills 索引(T-03 已把 skills 移到 volatile 尾)。
  与内核一致:只在会话开始或压缩重建时重读,不破坏前缀缓存。
- 未改 `plugins/`:插件系统只有固定的 system prompt section 锚点(`after_memory`),
  无法提供 profile-scoped 文件扫描 + 现有 memory 快照契约,按 PRD §5.4 登记为受控内核补丁
  (登记行见 `PRD.md` §5.4 表,已同步更新文件清单)。
