# T-09a 设备令牌:一次性配对码换长期 token,可单独撤销

检查时间:2026-11-03。状态:**已完成**(纯插件实现,无内核改动)。

## 实现

- 新增 `plugins/dashboard_auth/device_pairing/`(`__init__.py` + `plugin.yaml`),提供
  `DevicePairingProvider`(`supports_password` + `supports_session`,
  **刻意不支持** `supports_token`——设备令牌不得抵达 drain 等服务路由)。
- 配对码语义与 `gateway/pairing.py` 对齐:8 位无歧义字母表、1 小时过期、每 label 10 分钟
  1 次、失败 5 次锁定 1 小时(**全局**锁——label 是攻击者可选的,按 label 计数可被轮换绕过)、
  0600 文件、只落盐化 SHA-256 哈希,码与 token 均不写日志。测试断言常量与 `gateway/pairing.py` 相等。
- Token:`secrets.token_urlsafe(32)`(256-bit),哈希落 `dashboard/device-pairing/tokens.json`,
  明文只在兑换响应中出现一次。TTL 365 天。
- 流程:PC 端 `hermes device-pair generate --label <设备>` 打印配对码(码是操作者自己生成,
  生成即批准);手机端 `POST /auth/password-login {provider:"device-pairing", username:<label>,
  password:<码>}` 兑换;之后 `Authorization: Bearer` 走门禁 REST bearer 路径、`/api/ws?token=`
  走 WS 升级 token 路径——两者复用内核同一 `verify_session` 接缝
  (`hermes_cli/dashboard_auth/middleware.py` bearer leg + `hermes_cli/web_server_chat.py`
  `_ws_auth_reason` token leg),因此**无需注册任何新路由**。
- 撤销:`hermes device-pair revoke <label|id>` 删除哈希条目,下一次 verify 即刻失败(fail-closed)。
- 默认关闭:`config.yaml` 设 `dashboard.device_pairing.enabled: true` 才注册(fail-closed);
  开启后同时注册 `hermes device-pair` CLI 子命令。

## 为什么上一轮结论(「无完整身份模型」)被推翻

上一轮只看了 `token_auth.py` 的 provider 插槽,发现 `token_principal` 不会变成 `request.state.session`
(`ws-ticket` 路由要的是后者)而判受阻。实际路径在门禁中间件的 bearer leg:任何 bearer 都会过
`scan_session_providers` 的 `verify_session`,识别即挂 `request.state.session`;WS 升级同理。
`supports_password` 让 `/auth/password-login`(公开路由)承担「码换令牌」。三段都是现成内核接口,
插件只差 `complete_password_login` + `verify_session` 两个方法。

   协议合规、`register` 未启用时跳过、门禁端到端(无凭据 401 → 配对 → cookie/bearer 200 →
   ws-ticket 铸发 → `/api/ws?token=` 升级 token leg 接受 → 撤销后 401/token_invalid)。
2. 相邻回归:`test_dashboard_auth_password_login.py`、`test_dashboard_auth_ws_auth.py`、
   `test_dashboard_token_auth.py`、`test_dashboard_auth_gate.py` → **84 passed, 0 failed**。
3. 插件发现:`scan_directory(plugins/dashboard_auth)` 解析出 `key='device-pairing', kind='backend'`。
4. **真实服务器验收链**(临时 HERMES_HOME,`hermes serve --host 0.0.0.0 --port 9472`,门禁开启):

| 步骤 | 命令 | 结果 |
| --- | --- | --- |
| 无 token GET /api/auth/me | `curl` | **401** `{"error":"unauthenticated"}` |
| 无凭据 WS 升级 /api/ws | curl Upgrade 头 | **403** |
| CLI 生成配对码 | `hermes device-pair generate --label e2e-b` | 打印 8 位码(同 label 10 分钟限流亦实测复现) |
| 兑换 | `POST /auth/password-login` | **200** `{"ok":true}` + `hermes_session_at`(43 字符) |
| Bearer GET /api/auth/me | curl | **200** `{"user_id":"e2e-b","provider":"device-pairing","expires_at":1825203105}` |
| Bearer POST /api/auth/ws-ticket | curl | **200** ticket,ttl 30s |
| WS 升级 `/api/ws?token=<token>` | websockets 15.0.1 | **OPEN**,收到 `gateway.ready` 事件 |
| `hermes device-pair revoke e2e-b` 后 GET | curl | **401** |
| 撤销后 WS 再升级 | websockets | **403** `InvalidStatus` |

5. 同 label 10 分钟内第二次 generate 返回节流提示(实测)。
