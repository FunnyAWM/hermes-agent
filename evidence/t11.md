## 问题与修复

`source_check.check_for_updates()` 已有默认关闭的被动检查门禁，但桌面调用的 CLI `main()` 和
`GET /api/hermes/update/check` 没有传入 `passive=True`，因此绕过了该门禁。
缺少配置与 `updates.check: false` 都受影响。

- CLI 探针与 HTTP 轮询使用 `passive=not force`。`--force`、`force=true` 及显式切换通道仍可检查。
- 后端保留 `reason: disabled`、说明文字与 `behind: null`，不把未检查呈现为检查失败或已经最新。
- 桌面类型、store 与状态卡保留该结果，继续提供 **Check now**，实际点击使用强制检查。
  正在检查、正在安装的状态仍优先显示。文案复用已有翻译。
- 核心返回的 `supported: false` 保持原语义：被动关闭时尚未读取 checkout 元数据。
  仅状态卡将该情况呈现为可以手动检查，避免错误推断通道选择能力。

## 2026-11-06 真实 Electron 采集与 Google Fonts 违规修复

T-15 重建后 `apps/desktop/release/win-unpacked/Hermes.exe` 存在，本轮用真实 NetLog 完成了
Electron 侧采集，并修掉了采集器与产品默认配置各一处问题。

### 采集器缺陷（已修）

1. **真实 NetLog 用数字事件类型。** Chromium 写的是 `"type": 134`，名字表在
   `constants.logEventTypes`（name → id）。原实现只认字符串前缀，真实文件解析出 0 个主机，
   一次有外联的采集会被误判为干净。现按名字表反查，字符串与数字两种写法都覆盖。
2. **强杀会截断 JSON。** `proc.kill()` 在 Windows 走 TerminateProcess，日志停在半个 JSON。
   改为 `taskkill /PID`（WM_CLOSE）让 Electron 正常退出并收尾；超时才回退强杀。
3. **缺失/空日志不再算通过。** `netlog_report()` 把“没写成”与“无出站”分开，前者返回
   `blocked_reason`，整体 `ok=false`。
4. **不能再重定向 `USERPROFILE`/`HOME`。** 桌面 bootstrap 在二者指向新目录时会立刻退出，
   Electron 根本不启动。隔离改为 `HERMES_HOME` + `APPDATA` + `LOCALAPPDATA`。

### 首次真实采集发现的默认出站（已修）

第一份有效 NetLog 出现两条非回环目标：

- `https://fonts.googleapis.com/css2?family=Courier+Prime...`（`URL_REQUEST_START_JOB`，
  initiator `file://`，来自主题注入的 `typography.fontUrl`）；
- `[2001:4860:4860::8888]:443`（`UDP_CONNECT`，同一 DNS 解析链路）。

内置主题的 mono 栈并未引用这些远程字体（本来就是 bundled JetBrains Mono），字体请求是纯冗余
出站。修复：`apps/desktop/src/themes/presets.ts` 的五个内置主题删除 `fontUrl`；导入的第三方
主题仍可携带（显式用户行为，不属于默认配置）。新增
`apps/desktop/src/themes/presets.test.ts` 锁住“内置主题不得声明远程字体样式表”。

### 边界

- 桌面安装包不自带 Python 后端，应用停在首屏 bootstrap，本轮没有发起真实模型请求；结论是
  “默认配置、空闲桌面 + 空闲 headless serve 无外联”，不覆盖对话/工具流式请求。
- 需要验证模型端点出站时，用 `--allow <host>` 复跑；显式开启的检索/工具出站不属本项判据。
- 被动更新域名的静态默认值由 `test_passive_update_opt_out.py` 锁定，与本轮动态采集互补。
