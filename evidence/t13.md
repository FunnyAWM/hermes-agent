## 共享契约

`evidence/fixtures/memory-contract.json`（v1，2026-11-06）是 PC 与 Android 的共同基线：

- `MEMORY.md` 模型写入默认 3,000，`0` = 不限；`USER.md` 默认 0 / 不限；无合并上限。
- 条目分隔符 `\n§\n`（完整分隔，不是裸 `§`）。
- 计数：码点 + 簇尾归并；探针 `ab`=2、`é`（组合）=1、家庭 ZWJ=1、国旗对=1、标签序列=1。
- 类别：`work/study/life/health/finance/people/other` + 只读 `docs/`。
- `notes/docs/`：一层放平、文件名取来源、只读、计入清单、不参与摘要与合并。
- 根提示词必须存在且锚点文本 `running inside Hermes' local memory system` 位于 stable 首位。

## 实现

- `scripts/memory_contract.py`：从运行代码读取 `ENTRY_DELIMITER`、`MemoryStore.__init__` 默认值、
  `CATEGORY_DISPLAY_NAMES` / `WRITABLE_CATEGORIES`、`char_count` 探针与 `MEMORY_ROOT_PROMPT`，
  与 fixture 逐项比较；不再用正则抓源码。
- `scripts/check_upstream_memory.py`：改用共享契约，新增 `--json`；`--tag` 仍只读取该 tag 的
  `pyproject.toml` 版本，不 fetch。
- `scripts/check_upstream_upgrade.py` 把契约对齐作为升级预检的一步。

## 解除条件

拿到真实上游稳定 tag 后，按 `UPSTREAM_UPGRADE_CHECKLIST.md` §3 运行：

```bash
python scripts/check_upstream_memory.py --tag vX.Y.Z --json
```

把输出、tag/SHA、审查结论写入 `evidence/t13-<tag>.md`。若 drift 非空，先评估两端兼容与迁移/
回滚方案，不得只改版本号。
