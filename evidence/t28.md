# T-28 笔记清单软/硬上限与生命周期 —— 实现与验证

日期：2026-11-10
来源：PRD §5.4 登记表、记 04 / 05、T-28；对齐 Android `NoteScanner` / `NoteFrontMatter` / 设 13。

## 交付

- `hermes_notes/store.py`：`DEFAULT_SOFT_LIMIT=128`、`DEFAULT_HARD_LIMIT=None` 取代固定 64 截断；`NotesStore(soft_limit=, hard_limit=)`，硬上限才截断并在清单里明示 `(-N older notes beyond this index's N-entry hard cap ...)`；`hard_limit < soft_limit` 直接 `ValueError`。
- `hermes_notes/lifecycle.py`（新增）：`expires` / `lastUsed` 只在完整头部且唯一时解析（重复、非法、仅正文出现一律按未知）；超过软上限才删显式过期笔记，先归档 `<home>/.versions/<flattened>.<epoch-ms>` 再删，归档失败不删；`notes/docs/` 读取回写 `lastUsed` + `lastUsedBy: desktop`（同步来的 Android 轮次号不可比，未带标记一律不算候选），连续 N 轮未引用只列候选、经用户确认才删；`archive_before_overwrite` 覆盖 `memories/{MEMORY,USER}.md` 与 `notes/**.md`。
- 写前归档接线：`tools/file_tools.py`（`write_file_tool` / `patch_tool`）与 `tools/memory_tool_store.py::_mutate`；`SOUL.md` 与普通工程文件不归档。
- 设置：`hermes_notes/settings.py` 惰性读取 `memory.notes_soft_limit` / `notes_hard_limit` / `remove_expired_notes` / `document_unused_turns` / `organize_turns`（`config_defaults.py` 与 `agent_init.py` 已贴 FILE_LINES 上限，未再增长；非法值回退安全默认）。
- 每轮用户消息触发一次过期清理（`agent/turn_context.py`），O(n) 扫描带 ponytail 注释。
- `scripts/verify_pc_memory_notes.py` 的「固定 64」断言改为软/硬上限断言。
