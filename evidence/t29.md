# T-29 整理轮次（默认关，notes 维护）—— 实现与验证

日期：2026-11-10
来源：PRD §5.4 登记表、记 06、T-29；对齐 Android 整理轮次，按既有决议与 `background_review` 并存。

## 交付

- `agent/notes_organizer.py`（新增）：`memory.organize_turns`（默认 0 关闭）为间隔，每 X 条用户消息触发一次，`spawn_context_thread` 出生保证 profile 作用域；与在飞的 `background_review` 互斥一轮，避免并发辅助请求消耗双份额度。
- 复用 `build_cache_parity_fork`：父会话系统提示词与 `tools[]` 字节不变，整理请求自身是独立会话（不注入父历史、不改冻结前缀）。
- 作用域：白名单仅 `read_file/search_files/write_file/patch`，并以 `bind_notes_write_scope()`（ContextVar）把写入限定在 `notes/<category>/*.md`；`memories/MEMORY.md`、`memories/USER.md`、`SOUL.md`、`notes/docs/**`、非 `.md` 全部拒绝。整理请求不携带 `memory` 工具，也不触碰 `MEMORY.md`。
- 上下文：清单索引 + `notes/docs` 连续未引用候选（只告知、要求不得删除）。
- 不做 `.memory_incomplete` 标记：每次从当前笔记全量重建计划，失败下一轮自然重试，无需待办状态（与 Android 摘要回写的 CAS 场景不同）。
