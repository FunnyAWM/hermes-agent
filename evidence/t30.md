# T-30 Auto Review（工具调用前 LLM 授权审查）—— 实现与验证

日期：2026-11-12
来源：用户指令（复刻 `D:\VSCodeProjects\deepseek-harness\packages\experimental\auto-review\`）、PRD §5.4 登记表、T-30。

## 交付

- `approvals.mode: auto`（第四种模式）：每个工具调用执行前用辅助 LLM 输出严格 JSON ——
  `low+allow` / `medium+allow|deny` / `high+deny`；allow 直接执行，deny 转人工审批门，
  high 硬拒绝，非法输出或调用失败转人工（无人值守由人工门的 cron/unattended 策略阻断）。
- `tools/auto_review.py`（新增）：`REVIEW_POLICY`、`AutoReviewDecision`、`parse_review_response`、
  `build_review_messages`、`review_tool_call`、`gate_tool_call`、`should_review`。
  参数按不可信输入包裹；`utils.safe_json_loads` 严格解析并拒绝多余键；本地只读工具不审查；
  `approvals.auto_review.skip_tools` 可追加。
- 接入点：`agent/tool_executor.py::_dispatch_authorized_once`，顺序 scope → plugin `pre_tool_call`
  → pruned-arg → **auto review** → guardrails → dispatch；`messages` 从并发批次、顺序派发、
  terminal 批处理三条路径透传。
- 模式直通：`check_dangerous_command` / `check_all_command_guards` / `check_execute_code_guard`
  在 auto 下跳过人审；`_floor_block`（hardline、runtime 自删、`approvals.deny`）仍在之前执行。
- 刻意保留：`_run_approval_gate` 的 bypass **不含** auto（否则 deny 转人工会被自身放行）；
  `is_approval_bypass_active_for_session` 仍只认 off/yolo，使 MCP 信任、sandbox escalation、
  computer_use、Codex runtime 的独立门禁继续生效。
- 配置：`approvals.auto_review.{policy,history_messages,max_arg_chars,skip_tools}`；
  模型路由 `auxiliary.auto_review`（`_aux(30)`）。
- 三端清单：CLI `/approvals`、TUI `_APPROVAL_MODES`、Web `_select`、Desktop 类型/常量/菜单/i18n（8 语言）。
- 文档：`website/docs/user-guide/configuration.md`（Auto review 段）、
  `website/docs/user-guide/features/hooks.md`（`surface="auto_review"`）、PRD §5.4 登记行。
