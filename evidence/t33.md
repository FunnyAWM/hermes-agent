# T-33 · 双窗口删除后的会话列表同步（验证 + 修复）

日期：2026-11-13

## 结论

修复前 **不同步**，且有两个独立缺口：

1. **总线上只发「刷新」信号，不发 id。** 发送窗口的删除墓碑是 renderer 本地状态
   （`$removedSessionIds`），接收窗口拿到刷新信号后自己重拉，后端页已不含该行，但
   `mergeSessionPage` 的 keep set（固定、选中、working、打开中的 tile）会把旧行重新
   塞回 `$sessions`（`store/session.ts:755`），下一次删除看起来像没发生过。
2. **secondary / browser 窗口整条监听被跳过。** `use-desktop-integrations.ts` 在注册
   `onSessionsChanged` 之前直接 `return`。这类窗口没有侧边栏，不需要 `refreshSessions`，
   但会话选择器 / 命令面板的缓存页同样不该留着已删行。

## 修复

- `store/session-sync.ts`
  - 消息体升级为 `SessionsChanged { removed?: ids; released?: ids }`（旧窗口发的数字
    `1` 仍按「只刷新」解码）。
  - 墓碑镜像改在**模块加载时注册**的监听里做，排在任何业务订阅之前：处理器开始时
    墓碑已经就位，刷新合并不会再短暂复活该行。
  - `broadcastSessionsChanged(change?)` 携带 id；`onSessionsChanged` 语义不变。
- 广播调用点补 id：
  - 删除：`{ removed: removedIds }`（tip + row id + lineage root）
  - 归档：`{ removed: archivedIds }`
  - 恢复（侧边栏与设置页）：`{ released: [id, lineageRoot] }`，接收端同步解除墓碑，
    避免恢复后的行被远端墓碑长期遮挡
  - 新建 / 分叉 / tile 等纯新增路径仍发空对象（只刷新）
- `use-desktop-integrations.ts`：所有窗口都订阅；仅 `refreshSessions()` 受
  `isSecondaryWindow() || isBrowserWindow()` 限制，缓存页失效与墓碑镜像照常执行。

墓碑回收沿用既有链路：接收窗口的 `projects.tree` 快照不再列出该 id 时
（`store/projects.ts:508`）自动剪除；删除 RPC 提交后才广播，因此不存在「回滚了但
远端仍被墓碑遮挡」的路径。

## 验证

新增 `src/store/session-sync.test.ts`（5 条）：

- 另一窗口 `{ removed: [tip, root] }` → 本窗口两个 id 都进墓碑，并触发一次处理器；
- `{ released: [root] }` → 只解除该 id，tip 墓碑保留；
- 旧格式数字 `1` → 只刷新，不武装墓碑；
- 广播只投递给别的窗口，且发送端不武装自己的墓碑（本地已乐观逐出）；
- **回归主线**：固定行在 keep set 里时，无墓碑会被 `mergeSessionPage` 复活；收到
  远端 `removed` 后被过滤掉。

- 收到广播 → `invalidateSessionListQueries()` + `refreshSessions()` 各一次；
- secondary 窗口 → 仍失效缓存页，但不拉侧边栏；
- 卸载后取消订阅。
