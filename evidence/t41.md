# T-41 · 完整版安装时长异常：密封子集 venv 裁到 `[all]`

日期：2026-11-17

## 现象

`apps/desktop/release-full/` 的安装包安装耗时明显异常长。

## 实测（win32-x64，2026-11-17 构建产物）

| 项 | 实测 | T-38 设计值 |
| --- | --- | --- |
| 安装包 | 583 MB | ~200 MB |
| 展开 | **2.2 GB** | ~450 MB |
| 文件数 | **76,206** | — |
| `agent-payload/venv` | **1.4 GB / 59,933 文件** | 203 MB |
| ├ 其中 `.pyc` | 392 MB / 30,002 文件 | — |
| └ extras | **49 个** | `[all]` 9 个 |
| `agent-payload/tools` | 164 MB（仅 python 解释器，正常） | 144 MB |
| `agent-payload/hermes-agent` | 227 MB / 13,546 文件 | 其余预算内 |

venv 内最大项：`lark_oapi` 113 MB、`playwright` 109 MB、`googleapiclient` 109 MB、
`alibabacloud_dingtalk` 93 MB、`av.libs` 63 MB、`ctranslate2` 60 MB、`onnxruntime` 48 MB、
`piper` 45 MB、`nemo_relay` 29 MB、`sherpa_onnx` 28 MB、`botocore` 27 MB、`mistralai` 18 MB。

## 定位

根因：`scripts/bundles/native.py` 在密封子集（`HERMES_BUNDLE_TOOLS` 已设）下仍传
`all_extras=True`，即 `uv sync --all-extras`（只排 `[tool.hermes] opt-in-extras = ["kittentts"]`）。
这把全部 **49 个**可选集成装进 venv，而 `[all]` 政策（pyproject 2026-05-12 注释）只允许
9 个「每会话都可能用到」的 extras 常驻，其余应走首次使用时懒装。

安装慢的机制不是字节数而是**文件数**：NSIS 逐文件解压 7.6 万个条目，Windows Defender 对每个
新建文件做实时扫描；3 万个 `.pyc` 占其中 40%。

排除项：`load_prepared` 在 payload 安装/首启路径上**没有**调用者（只被 `finish_native` 与
`pm/client.py` 使用），安装慢与 payload 全量哈希校验无关。

## 被否方案：删 `.pyc`

`scripts/bundles/bytecode.py` 的 `bake_bytecode` 是性能契约：密封 payload 运行时把字节码写到
用户级缓存，不预烘则每次冷启动都在前台编译（#100461）。它还有**覆盖率断言**——
`_uncovered` 发现任何可解析模块缺 pyc 就直接 `raise ValueError`（"a fresh install would
cold-compile them every launch"）。删 `.pyc` 要么被断言拒绝，要么让每次启动重编，等于把安装
时间换成启动时间。裁 extras 后 `.pyc` 数量随模块数自然下降约 60%。

## 改动

| 文件 | 内容 |
| --- | --- |
| `scripts/bundles/native.py` | 新增 `_venv_sync_extras(only)`：全量包仍 `--all-extras`，密封子集改 `--extra all`；`build_environment` 传 `**_venv_sync_extras(only)` |
| `pm/features.py` | 模块 docstring 补密封子集的 `--extra all` 形态（`installed_extras` 探测实际安装，逻辑不变） |
| `tests/scripts/test_bundle_native.py` | `test_sealed_subset_venv_takes_all_but_the_full_bundle_takes_every_extra` |

能力影响：密封包内 `dingtalk / feishu / telegram / discord / slack / google-meet(playwright) /
piper / wake-* / bedrock / mistral / computer-use …` 不可用；启用时 `sync_venv` 被 sealed 守卫
拒绝并提示「安装新包升级」（与 T-38 既定的只读语义一致）。`[all]` 内的 9 个
（`cron / pty / mcp / uvloop / sms / acp / google / web / youtube`）保留。

## 追加：第二轮优化（2026-11-18，T-43）

第一轮上线后实测：安装包 583→**330 MB**，payload 2.2 GB/76,206 文件→**693 MB/29,539 文件**
（venv 1.4 GB/59,933 → 335 MB/13,092）。安装仍慢，继续压两处：

| 改动 | 收益 | 代价 |
| --- | --- | --- |
| `asar.unpack` 由 `dist/**` 收窄为 `dist/native/**` | -1,126 个渲染产物文件 / -50.9 MB 解压（原来只为 `hud-modifier-monitor.exe` 9.7 KB 服务） | 无 |
| 密封包 extras 从 `[all]` 去掉 `google`（`_SEALED_EXTRAS` 显式列 8 项） | -109 MB / 数千个 discovery 模块文件 | google-workspace skill（Gmail/Calendar/Drive）在密封包内不可用，需要时换包 |
| electron-builder `compression: 'store'` | 安装时 693 MB 顺序写入，去掉 LZMA 解码 | 安装包 330 MB → 约 1 GB |

已验证：`uv sync --frozen --dry-run --extra acp … --extra youtube` 解析成功且结果中不含
`google-api-python-client`；`tests/scripts/test_bundle_native.py` 16 过 0 败 4 跳；
after-pack 测试 3 过。

剩余文件数约 2 万是 `.py`/`.pyc`（venv + 源码快照）：`.pyc` 受 `bake_bytecode` 覆盖率断言约束
不能删，`.py` 是 Python 导入必需，已接近该方案下限。
