# T-42 · Auto Review 失效 + 沙箱提权引导缺失

日期：2026-11-17

## 现象

用户报：① Auto Review 档位完全不生效，本该自动通过的命令仍弹人工审批；② 沙箱隔离等级选择
不正确——`workspace-exec` 下需要提权时应申请 `full-access`，模型却改用 `read-only`。

## 定位

### ① Auto Review 每次都 400，失败即转人工

`HERMES_HOME/logs/agent.log`：

```
Auxiliary auto_review: using custom (Sage-S2.1-Flash) at https://discovery-api.intern-ai.org.cn/v1/
Auto review of tool terminal failed (BadRequestError: Error code: 400 -
  {'error': {'code': 'upstream_request_rejected',
             'message': 'Failed to deserialize the JSON body into the target type:
                         reasoning_effort: unknown variant `none`, expected one of
                         `low`, `medium`, `high`, `max`'}})
Tool skill_manage returned error: {"error": "AUTO_REVIEW_FAILED", ...}
```

`tools/auto_review.py::_review_reasoning()` 返回 `{"enabled": False}`（不为审查付思考预算），
在 custom profile 上投影成顶层 `reasoning_effort: "none"`。该端点用 Rust serde 反序列化，
`none` 不在枚举里 → 400。`gate_tool_call` 把不可用判定按 `FAILED` 处理 → 转人工 gate。

`agent/error_classifier.py` 本已有一类 `_REASONING_LEVEL_REJECTION_MARKERS`（「closed level
set 拒绝 disable」，如 Alibaba 的 `must be one of`），但只匹配两种措辞，**漏了 serde 的
`unknown variant` / `expected one of`**。分类失败 → auxiliary ladder 不进入 floor step-up →
每次 auto review 都花一次 400 再失败。

### ② 机制存在，但反馈没教模型用

提权链路本身是完整的：`terminal(sandbox=…)` schema（`terminal_tool.py:1745`）→
`_sandbox_escalation_scope`（`terminal_tool.py:1128`）→ 更宽档位走 `request_tool_approval`
人工审批 → 只对本次调用生效。`terminal.sandbox.escalation` 默认 True。

问题在阻断反馈：`local_command_sandbox.py::failure_note` 只写
「To widen it, change terminal.sandbox in <home>/config.yaml」——那是给用户的配置路径，
模型读到后没有可执行的下一步，于是改试一个更严的档位（`read-only`），命令依旧失败。

## 改动

| 文件 | 内容 |
| --- | --- |
| `agent/error_classifier.py` | `_REASONING_LEVEL_REJECTION_MARKERS` 增加 `unknown variant`、`expected one of`（serde 枚举措辞），命中后走既有的 floor step-up |
| `tools/environments/local_command_sandbox.py` | `failure_note` 补一句：对**本条命令**传 `sandbox="workspace-exec"` / `sandbox="full-access"` 申请更宽档位，用户会被询问批准，下一条命令恢复配置档位；原 config.yaml 路径保留（面向用户） |
| `tests/agent/test_error_classifier_reasoning_level.py` | `_SERDE_UNKNOWN_VARIANT_400` 加入 closed-level-set 参数化用例 |
| `tests/tools/test_sandbox_escalation.py` | `test_blocked_command_tells_the_model_how_to_ask_for_a_wider_level` |

未改动（刻意保留人工）：`_request_protected_instruction_approval`（AGENTS.md / SOUL.md 等受保护
指令文件）与 SSH config 写守卫每次都要人工审批，是安全设计，不随 `approvals.mode: auto` 放宽。
