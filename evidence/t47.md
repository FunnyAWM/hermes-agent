# T-47 · 安装器第二段进度条：7z 解压后再复制一遍整棵树

日期：2026-11-18

## 现象

安装进度条走完第一段（解压）后**回退**，随后停在一个固定百分比长时间不动。

## 定位

`node_modules/app-builder-lib/templates/nsis/include/extractAppPackage.nsh::extractUsing7za`：

```nsis
Nsis7z::Extract "$PLUGINSDIR\app-64.7z"      ; 解压到临时目录，有进度
CopyFiles /SILENT "$PLUGINSDIR\7z-out\*" $OUTDIR   ; 再复制到安装目录，无进度
```

同一份 payload 被写三遍：解压写临时目录 → `CopyFiles` 递归复制到安装目录 → 删临时目录。
`CopyFiles` 不刷新 NSIS 进度，所以进度条回退后停在一点不动；文件数越多，这段越长
（2.7 万文件时是分钟级）。

同一文件里还有一条永远直接落盘的分支：

```nsis
!ifdef ZIP_COMPRESSION
  nsisunz::Unzip "$PLUGINSDIR\app-64.zip" "$INSTDIR"
```

`NsisTarget.js:518` 里 `options.useZip` 就是它的开关。

## 改动

`apps/desktop/electron-builder.fork.cjs`：`nsis.useZip: true`。zip 直接解压到 `$INSTDIR`，
没有临时目录、没有复制阶段，进度条连续。

代价：zip(deflate) 压缩率低于 7z(LZMA)，安装包变大（推断 330 MB → 450–500 MB，待重打包实测）。
`compression` 保持默认，未改。

## 验证

| 项 | 结果 |
| --- | --- |
| `node -e "require('./electron-builder.fork.cjs').nsis.useZip"` | `true` |
| 重打包后安装实测（进度条连续、安装耗时、包体积） | 待填 |

### 2026-11-26 安装包解压回归

从报错的完整安装包中提取 `$PLUGINSDIR/app-64.zip`，其文件头为
`37 7A BC AF 27 1C`（7z）。electron-builder 27.0.0-alpha.6 默认开启差分打包，
归档生成器强制选择 7z，安装脚本则依据 `useZip` 调用 ZIP 插件。

关闭差分打包后，内嵌 ZIP 通过 CRC 校验。用原安装包里的 DLL 在静默 Unicode NSIS
探针中解压这个有效 ZIP，返回失败，输出目录为空。`nsis@1.2.1` 的 x86 ANSI 和 Unicode
目录提供了同一个 DLL。换用 `nsis-resources-3.4.1` 中的 x86 Unicode 插件后，探针返回
`success`。该 DLL 与 NSISunzU 原作者分发包中的二进制 SHA-256 一致。

| Windows x64 产物 | 实测 |
| --- | --- |
| 完整安装包 | 从成品取出 DLL 和 ZIP，在含中文及空格的目录解压，14,821 个文件与 `win-unpacked` 逐文件 SHA-256 一致，ZIP 全部条目的 CRC 通过 |
| Headless 安装包 | 同样提取和校验，1,203 个文件一致 |
| Headless 便携版 | 与安装版同时构建。实际启动便携 EXE，以 Electron Node 模式读取释放的 `app.asar`，SHA-256 与原始应用一致 |

本次验证的 `HermesBundled-0.3.25-win-x64-setup.exe` 为 340,527,521 字节，
SHA-256 为 `88688591e5b228b7e6f457205498af4a823d26afd748156d43061cfd4bdb91d1`。
检查在隔离目录进行，覆盖了解压步骤。安装向导交互、进度条连续性及覆盖安装耗时仍待实测。
