## 定位

`build-full.ps1` 的实际链路是 `pnpm run payload` → `scripts/bundles/stage.py`，**不是**
`scripts/bundles/desktop.py::_build_prepared`（后者只被 `build-bundle.ps1` 使用）。T-46 只改了
`desktop.py`，所以完整版的 `apps/desktop/dist-webapp` 一直还在包里——既没省下 1,086 个文件，
也白跑了一遍 vite。

`stage.py` 无条件执行四条前端构建（node-deps / icons / tui / web / webapp）并把三者作为
`frontends` 传给 `stage_native` → `finish_native` 种进 payload。

## 待办判断（需要构建日志才能定）

`_phase` 已在 `prepare_native` 里打印每个阶段的秒数。已知的候选优化：

1. **venv 重建**：`_prepare_native` 每次 `rmtree(venv)` 后跑 `build_environment`；uv 全局 cache
   命中后仍需建 8,000+ 文件。可加「prepared.json 的 revision/lock/extras 与当前一致则整步复用」，
   但需要设计轻量校验（不能每次全量哈希 1.2 万文件）。
2. **两次 git archive**：`stage.py` 为前端构建快照一次，`prepare_native` 又为 payload 快照一次。
3. **electron-builder 的 zip 压缩**：`useZip` 后走 deflate，`compression: 'store'` 会让打包与安装都快，
   但包体积显著变大（用户此前否决 store）。
